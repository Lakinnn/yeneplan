# YenePlan deployment and Telegram setup

## Important runtime note

This repository currently builds a **Node/Express application**. The build output is `dist/index.js`, started with `node dist/index.js`. A plain `npx wrangler deploy` expects a Cloudflare Worker entrypoint and Worker-compatible bindings; it does not automatically turn this Express server into a Worker. Before relying on a Workers deployment, confirm that the deployed URL serves `/api/trpc` and `/api/telegram/webhook` from this application. If those routes are unavailable, use the managed Node deployment for the API, or migrate the API to a Worker router with D1/Hyperdrive and R2 before moving the backend to Workers.

The fastest reliable arrangement is:

1. Keep this Node/Express app running at a public HTTPS API URL.
2. Put the frontend on the same URL or Cloudflare Pages.
3. Set `APP_BASE_URL` to the exact public URL users open from Telegram.
4. Configure the Telegram webhook against that API URL.

Do not put `TELEGRAM_BOT_TOKEN`, database credentials, or setup secrets in client-side `VITE_` variables.

## 1. Create the bot in BotFather

In Telegram, open **@BotFather** and run:

```text
/newbot
```

Choose a display name such as `YenePlan` and a unique username ending in `bot`, such as `yeneplan_bot`. BotFather returns the bot token. Copy it once and store it as a Cloudflare secret; do not commit it to GitHub.

Set the command menu. The application setup endpoint also registers these commands, but BotFather can be used as a fallback:

```text
/setcommands
```

Paste:

```text
today - See today’s tasks
add - Add a task to today
done - Complete a task
missed - Mark a task missed
later - Move a task to tomorrow
progress - Log today’s progress
mood - Log your mood
energy - Choose your energy pace
overwhelmed - Get one tiny next step
help - Show quick actions
```

The bot’s **Open YenePlan** button is generated by the application with a Telegram Web App URL. Users should open that button once after signing in to the website; the server validates Telegram’s signed `initData` before saving their chat ID.

## 2. Add variables in Cloudflare

For a Cloudflare Worker or Pages deployment, open:

**Workers & Pages → yeneplan → Settings → Variables and Secrets → Add variable**

Add these as encrypted secrets unless noted otherwise:

```text
TELEGRAM_BOT_TOKEN=<token returned by BotFather>
TELEGRAM_BOT_USERNAME=<username without the @>
TELEGRAM_WEBHOOK_SECRET=<random secret for Telegram’s webhook header>
TELEGRAM_SETUP_SECRET=<random secret used only for the setup request>
TELEGRAM_CRON_SECRET=<random secret used only by the reminder scheduler>
APP_BASE_URL=https://your-public-app-domain.example
```

Generate strong values locally with:

```bash
openssl rand -hex 32
```

`APP_BASE_URL` must be the public HTTPS URL, not a localhost URL and not a Cloudflare management URL. Redeploy after saving variables so the runtime receives them.

## 3. Register the webhook and command menu

After deployment, call the application setup endpoint once from a terminal. Replace the placeholders with your actual values:

```bash
curl -X POST https://your-public-app-domain.example/api/telegram/setup \
  -H "Authorization: Bearer YOUR_TELEGRAM_SETUP_SECRET"
```

A successful response contains `"ok":true`. This registers:

- `https://your-public-app-domain.example/api/telegram/webhook`
- Message updates and inline-button callback updates
- The bot command menu

If the response says `Telegram bot is not configured`, the deployment does not have `TELEGRAM_BOT_TOKEN` and `TELEGRAM_BOT_USERNAME` available at runtime. If it says `APP_BASE_URL is not configured`, add that variable and redeploy.

Check Telegram’s webhook status directly:

```bash
curl "https://api.telegram.org/botYOUR_TELEGRAM_BOT_TOKEN/getWebhookInfo"
```

The response should show the exact webhook URL and no persistent `last_error_message`.

## 4. Test the bot end to end

1. Open the bot and send `/start`.
2. Sign in to YenePlan in a browser.
3. Open YenePlan through the bot’s **Open YenePlan** button.
4. Return to Telegram and send `/today`.
5. Send `/add Read 5 pages`.
6. Tap the inline **Done** or **Miss** button.
7. Send `/mood 3`, `/energy low`, and `/overwhelmed`.
8. Open the website and confirm the task status and energy mode changed.

If `/today` says that the account is not connected, the website was not opened through Telegram’s Web App button, or the bot token used to validate `initData` differs from the token used to send messages.

## 5. Configure reminders

The application exposes:

```text
POST /api/telegram/reminders
```

It sends reminders only to users who have connected Telegram and enabled reminders in Settings. It also includes inline Done buttons and an Open today button.

A Cloudflare Cron Trigger cannot automatically attach an arbitrary `Authorization` header to a normal HTTP request. Use one of these safe options:

- Create a small scheduled Worker that runs on a Cron Trigger and fetches the endpoint with `Authorization: Bearer YOUR_TELEGRAM_CRON_SECRET`.
- Use another trusted scheduler that supports custom headers.
- During testing only, leave `TELEGRAM_CRON_SECRET` unset and protect the endpoint at the network or routing layer; do not use this for a public production endpoint.

The scheduler should call the endpoint at a cadence such as every 15 minutes. The endpoint should eventually filter by each user’s saved timezone and reminder time before sending; for an exact per-user schedule, add that filtering before production launch.

## 6. Cloudflare production checklist

- Confirm the public app serves `/api/trpc` and `/api/telegram/webhook`.
- Confirm all Telegram and database values are encrypted secrets.
- Confirm `APP_BASE_URL` matches the URL users open.
- Run the setup request after every webhook URL or bot-token change.
- Check `getWebhookInfo` after deployment.
- Test `/today`, `/add`, inline Done, `/progress`, `/mood`, `/energy`, and `/overwhelmed`.
- Do not expose private tasks, notes, mood, or vision data in community or Telegram messages beyond the linked user’s own chat.
